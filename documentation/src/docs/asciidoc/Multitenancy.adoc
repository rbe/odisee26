[[multitenancy]]
Multitenancy
~~~~~~~~~~~~

A logged-in user has a private directory under `$ODISEE_HOME/var/user/{name}/`.
Templates are in `template`.
Merge inputs are in `work`.
Generated files are in `output`.
The job list is `jobs.json` in that same directory.
There is no shared `var/template` fallback.

[[adding-odisee-users]]
Adding Odisee Users
^^^^^^^^^^^^^^^^^^^

The server reads `$ODISEE_HOME/etc/users`.
`java -jar` does not read `odisee-users.xml`.

A line is `username bcrypt-hash` or `username bcrypt-hash admin`.
A line that starts with `#` is a comment.
The hash is bcrypt.
The file does not store the password.

If `etc/users` is missing, the server creates the first admin only when both `ODISEE_BOOTSTRAP_USER` and `ODISEE_BOOTSTRAP_PASSWORD` are set.
Otherwise it creates no users.
There is no default password.

The next user is `odictl user NAME PASSWORD`.
The command appends a bcrypt line to `etc/users` and creates `template`, `work`, and `output` under `var/user/NAME/`.
The new user is not an admin.
A bad name fails.
An existing user fails.
There is no default password.
The person who can run `odictl` is the admin.

[[permissions]]
Permissions
~~~~~~~~~~~

`etc/users` is readable and writable by the server user only.
`odictl user` writes that file.
This server does not configure SFTP.

[[access-to-http-service]]
Access to HTTP Service
^^^^^^^^^^^^^^^^^^^^^^

`POST /odisee/document/generate` requires HTTP Basic.
No login is HTTP 401 and does not generate a document.
Any authenticated user may run macros.
The macro name, library, and language must be plain names.
A bad name is HTTP 400.
`GET /odisee/ready` stays anonymous.

[[callback-hosts]]
Callback hosts
^^^^^^^^^^^^^^

`POST /odisee/document/jobs?callback=https://host/path` stores that URL on the job.
Odisee POSTs only when that host is listed in `$ODISEE_HOME/etc/callback-hosts`.
`odictl callback-host HOST` appends a host.
A URL whose host is off the list does not get a POST.
`POST /odisee/document/generate` does not read a callback.
