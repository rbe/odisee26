# Delivery, jobs, and callbacks stay per user

## Rule

- `odisee/@delivery` (JSON `delivery`) is `stream`, `store`, or `both`. The default is `stream`.
- `stream` returns the file as the body. `store` writes the object to the bucket of the user and returns JSON `bucket` and `key`. `both` returns the file, stores a copy, and names it in the `X-Odisee-Object` header.
- Each user has one bucket, one line in `$ODISEE_HOME/etc/buckets`, read on each store. The request cannot name a bucket, an endpoint, or a credential. The server chooses the key. A user with no line is rejected for `store` and `both`.
- Odisee does not expire, delete, or set a lifecycle on a stored object.
- `POST /document/generate` stays synchronous. A synchronous call deletes its request directory unless `archive/@files` is `true`.
- `POST /document/jobs` returns HTTP 202 and a job id. The job list is `var/user/{name}/jobs.json`. A job of another user is HTTP 404.
- A callback is a query parameter of `POST /document/jobs` only. Odisee posts to it only when the host is a public external host listed for that user in `$ODISEE_HOME/etc/callback-hosts`. Loopback, link-local, private, and internal names are rejected. `CallbackPoster` resolves the host once and connects to that address without redirects.
- `image/@url` is `http` or `https` on a public host. Any other URL is HTTP 422.

## Why

A request that could name a bucket or a callback target would let one user write to another account or reach an internal host (old labels B49, B54). The admin configures each target in `$ODISEE_HOME/etc` through `odictl` ([ADR-0004](ADR-0004.md)).
