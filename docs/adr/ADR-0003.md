# OpenID Connect login and per-user directories

## Rule

- A client sends `Authorization: Bearer` with a token from the client-credentials grant. The server checks the issuer and the audience in `$ODISEE_HOME/etc/oidc`.
- The client id is the Odisee user. A username claim on the token does not select a different user. The UI client `odisee-ui` uses `preferred_username`.
- The caller comes from the security context (`callerFromContext`), not from `request.userPrincipal`.
- There is no password file and no HTTP Basic login. There is no hardcoded user.
- No login is HTTP 401 and generates no document.
- `GET /ready` is anonymous. Every other product route needs a login.
- Templates, merge inputs, output, jobs, and revisions resolve only under `var/user/{name}/`. There is no shared `var/template` directory. One user cannot read another user's template, revision, or job. Such a request is HTTP 404.
- Any authenticated user may run a macro. The macro name, library, and language are plain names ([ADR-0001](ADR-0001.md)).
- SFTP homes are not implemented.

## Why

The Grails app had no authentication, then a bcrypt password file in wave 4 (old labels B21, B22, B31). OpenID Connect replaced the password file, so a person never sends a password to Odisee. A password file, a second config channel, or a shared `var/template` is a regression.
