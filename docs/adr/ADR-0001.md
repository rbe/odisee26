# One v2 request contract and one status decision

## Rule

- The request schema is v2, `webservice/src/main/resources/xml/v2/request.xsd`. A document with no namespace has the same v2 shape.
- A v3 or v2.6 namespace is HTTP 400. Those schemas are not shipped.
- `RequestSchema` validates the body before generation. The parser rejects a `DOCTYPE` and does not resolve external entities.
- `Compression.readLimited` caps the raw body at 8 MiB and the expanded body at 32 MiB. Either cap is HTTP 400.
- `HttpStatuses` is the only status decision: 400 for a bad request, 401 for no login, 404 for a missing template, 422 for an instruction that fails, 503 for the office pool, and 500 for an unexpected server error.
- The controller does not close the stream after `HttpStatuses` wrote the error body.
- `OutputFormats` is the format decision. `output/format/@type` is the format when present. `template/@outputFormat` applies when `output` is absent. A `.pdfa` file name is the PDF/A fallback when the request sets no PDF version.
- The Java client schema `clients/client-java/src/main/schema/request.xsd` is a copy of the v2 schema. The PHP, VB.NET, and Oracle clients build the same v2 shape.
- Product HTTP is `POST /document/generate`, `POST /document/jobs`, `GET /document/jobs/{id}`, `GET /template/{name}`, and `GET /ready`. There is no HTTP admin route.
- A request name, a macro name, a macro library, and a macro language go through `SafePaths.requireSimpleName`. A bad name is HTTP 400.

## Why

Before wave 2 the server accepted v2 and v3 shapes, returned HTTP 400 for every error, and read unbounded bodies (old labels B6, B8, B9, B18, B19). One schema and one status decision let a client tell its own error from a server error. Administration goes through `odictl` ([ADR-0004](ADR-0004.md)), so HTTP stays the product surface.
