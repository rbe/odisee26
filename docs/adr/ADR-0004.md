# odictl is the only management path

## Rule

- Management is `odictl` only. `odictl` stays bash. Bash is in the service image.
- The server reads configuration only from `$ODISEE_HOME/etc`, and reads it on use. There is no second config channel. One directory is mounted into every replica.
- A missing or blank `ODISEE_HOME` is an `OdiseeException`. The environment value wins and is absolute. The default for a user install is `$HOME/.local/share/odisee`.
- `odictl user NAME` creates the Keycloak user, a confidential client whose id is `NAME`, and `var/user/NAME/template`, `var/user/NAME/work`, and `var/user/NAME/output`. It prints the client id and secret.
- `odictl callback-host USER HOST` appends `username host` to `etc/callback-hosts`. `odictl bucket USERNAME ENDPOINT REGION BUCKET ACCESSKEY SECRET` writes the line of that user in `etc/buckets`.
- Commands that write `etc` lock it. Linux uses `flock`. Without `flock`, the lock is the directory `etc/.odictl.lock.d`, removed when `odictl` exits.
- `odictl`, `odipost`, and `odiwatchdog` source `odilib`. A bash older than 4 re-execs the entry script with `/opt/homebrew/bin/bash` or `/usr/local/bin/bash`, or exits 1 with one line.
- The container command is `/home/odisee/entrypoint.sh`. It starts LibreOffice with `odictl -q start-inst`, then runs `java -jar` in the foreground.
- Linux office port checks read `/proc/net/tcp` and `/proc/net/tcp6`.
- The operator text is the Lifecycle section of `documentation/src/docs/asciidoc/AdministratorsGuide.adoc` and `documentation/src/docs/asciidoc/Multitenancy.adoc`.

## Why

The person who runs `odictl` on the host is the admin, so the server needs no admin route and no admin login. One config directory means a replica cannot read a different setting from a second source. The macOS rules exist because `/bin/bash` 3.2 and a missing `flock` broke `odictl` (old labels B35, B36).
