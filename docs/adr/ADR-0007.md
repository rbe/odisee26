# Make, Podman, tests, and the book

## Rule

- The `Makefile` is the interface. Its header comment is the how-to. `make help` lists every target.
- Podman is the only container engine.
- Gradle runs in the Podman image of `gradle/Containerfile`. The host needs no JDK. The targets that start containers give Gradle the Podman socket of the host and the host network.
- A port that a container publishes on the host is a user port above 1024. Then no root rights are needed.
- `make test` runs the unit tests and starts no container. `make test-office`, `make test-minio`, `make test-keycloak`, and `make test-java` start their own containers. They do not use the compose stack of `make stack`.
- `make test-java` is the office proof. It is a CI job and does not gate a publish.
- The book under `documentation/` stays AsciiDoc. `packageDistribution` renders it into the zip under `docs/`. `README.md` stays the GitHub landing page.
- The Linux zip holds the service, `odictl`, the Java client, the LibreOffice extension, and the HTML book. The JavaFX jar stays out of the zip.
- The VB.NET client is not a CI job.
- The service image copies named files. It excludes `.claude/`, `CLAUDE.md`, and `docs/`.
- The divergences of this repository from the pipeline contract are in `docs/pipeline-rules.md`.

## Why

A laptop and CI run the same targets, so a CI failure can be run again on a laptop. The LibreOffice, MinIO, and Keycloak tests need Podman on the host, so they stay out of `make test`. The zip is the installable product, and the image is the other delivery.
