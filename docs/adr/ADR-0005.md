# The office pool comes from etc/odiinst and has deadlines

## Rule

- `OdiinstParser` reads host and port from `etc/odiinst`. The pool dials those addresses. Comments and blank lines are skipped.
- The optional 8th field is the pool group. A blank field is `group0`. The v2 `<group name="..."/>` selects the group. A missing `<group>` is `group0`. Each group polls its own queue.
- When the text of `etc/odiinst` changes, the pool in this JVM reloads it. Reload closes retired idle connections, and a retired in-flight connection is closed on return.
- `fetchConnection` tries up to one slot per configured address, then throws `OdiseeServerException`. Startup fails when no connection bootstraps.
- UNO `open`, instructions, and `save` have a deadline (`UnoCall`, default 120 s, `odisee.uno.deadline.ms`). On the deadline the server closes the document, drops the slot, and stops the local `soffice`, so `odiwatchdog` restarts it.
- `GET /ready` is HTTP 200 only when at least one office port accepts a UNO connection, otherwise 503. The body holds the pool gauges.
- A failed health check drops a remote host and does not signal a local `soffice`.
- The unused office stack (`OOoConnection`, `OOoConnectionManager`, `OOoProcess`) stays deleted.

## Why

The pool ignored the ports in `etc/odiinst`, kept only the last host, and a wedged `soffice` held a slot until the JVM exited (old labels B10, B11, B14, B47, B48). One pool, read from one file, with a deadline on each UNO call keeps the service up when one office instance fails.
